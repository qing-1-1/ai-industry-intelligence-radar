# Muse 运营商新闻接入

Muse 向 `main` 分支的 `data/muse/news.json` 写入 JSON 新闻列表；该文件更新会触发 `Radar daily` 工作流。工作流读取当前提交、采集其它来源、去重、用现有 AI 评分和整理，随后部署网页。原有的每日定时任务也会继续运行。每次执行都会调用原有 AI 模型，可能发生费用、限流或失败；提交文件不等于网页立即更新。

## 格式

文件必须是 UTF-8 JSON 对象，`items` 是数组（即使只有一条也必须是数组）。以下仅为格式示例，不是真实新闻，不能作为实际内容提交：

```json
{
  "items": [
    {
      "title": "示例标题",
      "url": "https://example.com/news/123",
      "source": "示例来源",
      "published_at": "2026-11-17T09:30:00+08:00",
      "summary": "仅根据原文撰写的简短摘要。",
      "image_url": "https://example.com/news/image.jpg"
    }
  ]
}
```

`title`、`url`、`source`、`published_at` 必填；网址必须是 HTTP(S)，时间必须是带时区、含时分的 ISO 8601 格式。`summary` 和 HTTPS `image_url` 可省略。未知或仅知日期而不知道时间的文章不要编造时间，不能导入。Muse 文件中的有效新闻不受 25 小时窗口限制，文件里所有有效条目都会参与处理；未来时间会被跳过，未通过分类、评分或去重的新闻也不会显示。其他来源仍按 25 小时采集。

同一天多次成功运行时会保留当天已有条目，同 URL 的新结果会替换旧结果。该去重不保证识别所有跨站转载和跨日重复。URL 和摘要等将发送给配置的模型服务；仓库为公开仓库，不要放密钥、私人资料或受限内容。

## 运维

为覆盖晚发现的新闻，建议 Muse 在文件中保留最近 96 小时的有效条目。系统不对该文件设置发布时间下限；每次运行仍可能重复分析保留的旧条目，因此会增加模型调用。


文件更新后的运行记录可在仓库 Actions → Radar daily 中查看。`max_candidates` 留空时不设置 AI 候选数量上限；其他来源的 25 小时时间窗、源站返回数量、相关性评分、去重和接口限流仍可能减少结果；Muse 文件不会按 25 小时筛选。若模型请求全部失败，工作流不会发布本次结果，也不会虚构补充新闻；修复后可重新运行任务。
