<a id="item-radar-industry-3"></a>
### [SageMaker Inference 支持 NVIDIA Multi-Instance GPU 分区以提升 GPU 利用率](https://aws.amazon.com/blogs/machine-learning/sagemaker-inference-now-supports-multi-instance-gpu-to-maximize-gpu-utilization-for-model-endpoints/) ⭐️ 7.0/10

AWS 于 2026 年 11 月 6 日宣布，Amazon SageMaker Inference 现已支持 GPU 分区，借助 NVIDIA Multi-Instance GPU（MIG）将一块物理 GPU 划分为多个独立分区。每个分区获得固定的计算单元份额和专用内存块，隔离由硬件强制执行。这使得客户可以在一块 GPU 上部署多个模型，并按模型实际需要选择新代加速器的一部分而非整颗 GPU，从而提高 GPU 利用率并降低推理成本。

rss · AWS Machine Learning · 11月6日 18:01

**「关键能力与实现方式」** GPU 分区基于推理组件（inference components）构建，分区是组件在申请 CPU 和内存的同一位置申请的一种资源。单模型端点、无服务器端点和异构实例池不支持分区。

MIG 可将一块 GPU 最多划分为七个实例（具体上限取决于加速器，不超过七个），每个实例拥有独立的计算、缓存、内存和内存带宽。由于划分在硬件层面完成，可带来可预测的延迟、故障隔离、按需容量、无冷启动、租户隔离以及可预测的规划与成本分摊等保障。

在实现上，GPU 分区在现有 API 调用中新增两个可选字段，没有新增 API 操作、资源类型或 IAM 操作；省略这两个字段的端点行为与现状完全一致。其中 AcceleratorPartitionLayouts 字段用于 CreateEndpointConfig 中的生产变体，声明每颗加速器如何划分，例如在 ml.p4d.24xlarge 上使用 mig-4g.20gb、mig-2g.10gb、mig-1g.5gb 三种分区类型。A100 有七个计算切片可划分，上述布局用满七个，因此 p4d 上的八颗 A100 各可承载相应模型。

使用边界方面：最大分区数取决于加速器且不超过七个；MIG 只允许在分区空闲时更改布局，在 SageMaker AI 上意味着需在创建端点时选定布局；需要多颗 GPU 的模型仍需使用完整设备。

客户此前若模型数量多于加速器，可选方案包括：运行更少、更大的端点并加大批处理（仅适用于可互换模型）；使用多模型端点（按需加载卸载，但模型共享设备无隔离，未加载模型首次使用有加载惩罚）；或迁移到自管 Kubernetes（MIG 可用，但需自行处理驱动版本、分区配置、设备插件和调度）。Salesforce 从需求定义到初始实现验证全程参与此项工作。

**「背景」** 在引入 GPU 分区之前，部署到 GPU 端点时可申请的最小 GPU 单位是一整颗加速器。这带来两方面限制：实例能承载的模型数量受加速器数量限制（例如 ml.p4d.24xlarge 有八颗 A100，无论每个模型需要 40 GB 还是 14 GB，都只能承载八个模型）；同时每次部署都只能选择部署到整颗 GPU，随着并发和提示长度增长，旧实例上的整颗 GPU 可能不够用，而新实例上的整颗 GPU 又超出模型实际所需，导致服务不足或为用不到的能力付费。

### [Greenlight Financial 基于 Amazon Bedrock AgentCore 构建自主 SOC 解决方案](https://aws.amazon.com/blogs/machine-learning/how-greenlight-financial-built-an-autonomous-soc-solution-on-amazon-bedrock-agentcore/) ⭐️ 6.0/10

Greenlight Financial 基于 Amazon Bedrock AgentCore 构建了名为 Luna 的自主安全运营中心（SOC）解决方案，每月可在无人工干预的情况下解决超过 90% 的、多达 4,000 起安全与风险案件。Luna 采用分层多智能体架构，并使用 AgentCore 运行时托管智能体代码、使用 AgentCore 记忆支持其分层多智能体系统。

rss · AWS Machine Learning · 11月6日 16:55

**「关键数据与架构细节」** Greenlight 的 SOC 每月接收 3,000–4,000 条安全与风险告警，来自四个主要来源：暗网泄露卡、身份与访问异常、基础设施告警（EDR、SIEM、资产清单等）、金融风险事件。人工分析师处理单个案件需 15–30 分钟。

Luna 采用分层监督者架构：Tier 1 监督者在 Amazon VPC 内通过 AgentCore 运行时运行，编排超过 30 个专业化智能体（涵盖身份与访问、终端检测、可观测性、资产清单、数据分析、支付处理、客户体验、客户支持、代码仓库、项目跟踪、威胁情报、SOAR 自动化等域），常规案件的中间分诊时间为个位数秒。案件通过 Amazon API Gateway（暴露 Luna Queue API 和 MCP 端点）以及 Tines SOAR 自动告警接入。

超出 Tier 1 置信阈值的案件（约 10%）升级至 Tier 2 监督者，其使用具备扩展推理能力的基础模型，跨 3–5 个数据源链式推理以建立因果关系，并生成含证据链的调查报告供人工复核。Tier 2 通过 Amazon EventBridge 速率触发器和 Amazon SNS 队列完成信号按计划批量处理，也可按需处理紧急升级案件。

**「背景」** Greenlight Financial 为家庭提供金融产品，包括借记卡、储蓄工具以及 Family Hub 和 Pet Tracker 等互联设备，并按照与大型银行相同的监管要求大规模处理敏感金融数据。该案例还涉及从 SOC 用例扩展到金融风险分诊，并使用情景记忆（episodic memory）支持持续学习。
