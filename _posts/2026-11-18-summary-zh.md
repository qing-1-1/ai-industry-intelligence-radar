### [NVIDIA 在 SC26 发布面向科学的 AI 代理工具、Rubin HPC GPU 与量子合作](https://blogs.nvidia.com/blog/ian-buck-sc26/) ⭐️ 9.0/10

2026 年 11 月 17 日，NVIDIA 副总裁 Ian Buck 在芝加哥 SC26 大会的特别演讲中，宣布了 Nemotron for Science 科学 AI 代理工具、Rubin HPC GPU、扩展的 Vera CPU 平台，以及与 IBM 和费米国家加速器实验室的量子计算合作。

rss · NVIDIA Blog · 11月17日 14:00

**「关键发布与数据」** Nemotron for Science 将 Nemotron 3.5 Super VL 开放模型与新的开放化学数据集及生命科学、化学的后训练配方结合，研究人员可在 DGX Spark、工作站或自有超算上本地运行。在阿贡国家实验室，用该工具包构建的代理通过单条提示规划并测试假设、选择模拟，最终识别出两个新的结合位点。

Rubin HPC 是 Vera Rubin 平台中的新 GPU，支持 FP64 至 FP4 精度，增加稀疏数据加速，采用第七代 NVLink 互连，CUDA 核心超过 50,000 个，约为 Hopper 的三倍，预计 2028 年推出。

德国气候计算中心 DKRZ 已为其 HLRE-5 超算选择 Vera CPU，预计 2028 年初交付，加入此前德州先进计算中心已公布的 Vera 系统。

量子方面，Jülich JUPITER 超算上的模拟显示，magic state cultivation 技术可将单个逻辑步骤所需操作减少十倍，该成果将加入 CUDA-Q。NVIDIA 与 IBM 将 DGX B200 系统与 IBM 量子计算机（含 IBM Quantum Nighthawk）配对，共建量子协同设计平台。新的 CUDA-Q 解码算法 TCBP-JOBS 将纠错研究计算从 12 周缩短至 45 分钟，目标是将解码延迟从约 300 微秒降至 10 微秒。

网络方面，Buck 展示了 NVIDIA 光子共封装光学交换机在 Lambda 的首批部署之一，称其在位错误和链路抖动方面的可靠性提升 15 倍。

**「背景」** Buck 在演讲开场回顾了 20 年前在佛罗里达州坦帕 SC06 教程上首次公开介绍 CUDA 的经历，并表示 NVIDIA 现已提供超过 1,000 个 CUDA-X 库。他提出，新的科学计算栈将是模拟、AI、量子与代理的结合，其中模拟始终处于核心位置。

### [中关村两院开源材料科学智能体 MatOS，资产库含 3,135 个数据集](https://www.qbitai.com/2026/11/510652.html) ⭐️ 8.0/10

北京中关村学院、中关村人工智能研究院（中关村两院）于 2026 年 9 月发布年度科研进展——面向材料研发的科研智能体系统 MatOS，由中关村两院 AI 材料研究所团队构建。目前 MatOS 已正式开源，技术报告发布在 arXiv，代码在 GitHub 公开。该系统将数据、知识、工具、技能、角色和工作流统一组织为科学资产，支持研究者和 MatOS 自身在已有资产之上构建新能力，通过有状态工作流执行研究任务，并将经过检查与审查的资产修订用于后续研究。

rss · 量子位 · 11月17日 06:09

**「关键数据」** 资产库规模：3,135 个数据集、386 项技能、104 个工作流、51 个专家角色，并集成 48 款材料计算软件。

基准评测（采用 GPT-5.4 底座）：在端到端自主科研基准 ResearchClawBench 上，MatOS 平均得分 19.46，较最佳基线 MIRA 高 11.15%，较 Codex CLI 高 33.6%；材料任务较 MIRA 高 18.7%，较 Codex CLI 高 80.8%。换用 DeepSeek-V4-Flash 时平均得分 19.20，同样高于全部基线。

成本：DeepSeek-V4-Flash 配置单任务平均成本约 0.85 美元，不到 Codex CLI（2.70 美元）的三分之一；GPT-5.4 配置以约 3.78 美元成本取得最高得分。

工具调用基准（以 DeepSeek-V4-Pro 为底座）：MatTools 上 MatOS 完整问题成功率 97.96%，高于 Codex CLI 的 95.92%和 Claude Code 的 89.80%；子任务成功率 97.10%，另两者为 95.65%和 91.30%。SciAgentGym 上 MatOS 案例成功率 59.5%，另两者为 57.1%。

研究案例：从 30,364,908 个初始结构中筛选出 97 个固态电解质候选，计算电导率最高达 59.0mS/cm；面向半导体封装的合金配方搜索中，286 个配方最高得分从 0.534 提升到 0.927，得分最高的 Pb–Ag–Pt–Sn 系合金预计在 297.75°C 开始熔化，升温 4.55°C 后液相比例达 80%；开发的 DuoCompNet 在固定测试集上平均绝对误差从 28.40°C 降到 3.18°C，比次优的 Roost 低 13.6%；训练数据选择方法 RarityGuard-MP 从约 126 万个结构中选出 10 万个训练机器学习势，模型能量、力和应力综合误差比 DIRECT 方法低 3.10%。

**「背景」** 材料研究对智能体系统提出三方面要求：数据库、模拟软件和机器学习势不断出现，要求系统无需重建即可接入新能力；研究跨越文献分析、计算和实验，要求系统能在长周期任务中保存状态、检查结果；模拟时长、采样策略等经验多来自实践，系统要能存储并在后续任务中复用。MatOS 以三大设计回应：分层科学资产图组织并扩展研发能力，有状态自适应工作流调用资产执行任务并保存证据，证据驱动的资产进化将可复用经验转化为经过检查与审查的资产修订。资产保存在模型之外，基础语言模型参数保持不变，资产也不绑定特定模型，评测中同一套 MatOS 分别搭配了 GPT-5.4 和 DeepSeek 系列模型。团队表示下一步将接入仪器和实验流程，使从计算筛选到实验验证的证据能在同一系统中关联。

### [GitHub Agentic Workflows 正式可用：单次运行默认预算 10 美元](https://www.infoq.cn/article/lMs1bM1muspglUjMr1l3?utm_source=rss&amp;utm_medium=article) ⭐️ 8.0/10

GitHub 宣布其开源项目 Agentic Workflows 正式可用。该项目可在 GitHub Actions 中运行编码智能体，处理 Issue 分类、CI 故障分析等代码仓库任务。智能体启动时仅拥有只读权限，其提出的更改由持有独立写入令牌的作业应用，并运行在由 Agent Workflow Firewall 保护的沙箱容器中，威胁检测作业会在应用修改前扫描变更。项目于 2026 年 6 月进入公开预览阶段。

rss · InfoQ 中文 · 11月18日 08:00

**「关键数据与产品变化」** 定价与限额方面，GitHub 文档将 AI Credit（AIC）价格定为每个 0.01 美元，每次运行上限为 1000 AIC（即 10 美元）。企业控制参考文档还规定了每天 5000 AIC、每次威胁检测运行 400 AIC，以及智能体步骤最多运行 20 分钟，组织可覆盖这些设置。已结束实验阶段的 gh aw forecast 命令可估算每月 AIC 支出，含威胁检测费用。

公开预览以来新增了对 Actions Runner Controller（ARC）的支持，ARC 是面向自托管 Runner 的 Kubernetes Operator，可配合 Docker-in-Docker（DinD）使用，使智能体能在 Runner Pod 内启动自己的沙箱容器。项目指南指出，ARC 默认以特权容器方式运行 DinD Sidecar。

开发者用自然语言 Markdown 描述任务并通过 YAML Front Matter 配置，项目会将其编译为标准 Actions 工作流，复用现有 Runner 组和策略限制；团队既可用 Copilot，也可接入其他编码智能体。

**「适用范围与安全边界」** 该项目面向 github.com 上的 GitHub Free、Team 和 Enterprise 用户开放，默认使用的 Copilot CLI 引擎需要 Copilot 许可证。GitHub 常见问题指出，可复现的构建和测试仍更适合用传统 Actions，智能体工作流适用于需要理解或生成内容的任务。

隔离措施存在局限：常见问题指出这些保护不会自动覆盖直接授予的写入权限，也不适用于工作流作者自行添加的自定义作业，安全性取决于具体配置；作者可添加 GitHub Environment 保护规则，要求写入作业运行前经审核人员批准。

参与测试的 freenet 中间件团队负责人 Sascha Mirow-Stanitzok 认为默认预算对 Issue 分类过于宽松，因此将每次运行限制为 100 AIC、15 轮交互和 10 分钟；他表示仅要求智能体忽略 Issue 文本中的指令并不能真正保护工作流，对会修改代码或创建 Pull Request 的工作流不会采用同样模式。埃森哲高级经理 Ben Alton 在公告中称一位负责人估计每周在开发工作上节省 29 小时，公告未解释该数据的测量方式。GitLab 的 Duo Agent Platform Flow 采用不同方案，以复合身份运行并将服务账户与发起请求的人类用户绑定，触发操作必须由人类发起，一个 Flow 无法启动另一个 Flow。

Amazon SageMaker AI 推出 KV 缓存感知路由（KV\_AWARE），这是实时端点的一种新路由策略。它依据模型容器上报的缓存状态，将每个请求发送到已持有该提示较长缓存匹配且负载不过高的实例，面向使用多轮对话、长共享提示或高负载场景的 LLM 服务团队。启用方式为在模型中添加一个环境变量让容器上报缓存内容，并在端点配置中将 RoutingStrategy 设为 KV\_AWARE；客户端调用 API 保持不变。

rss · AWS Machine Learning · 11月17日 21:11

**「关键数据与产品变化」** 工作原理分三部分：容器通过 SM\_VLLM\_KV\_EVENTS\_CONFIG 开启事件，在每次存储或驱逐缓存条目时发布 KV 缓存事件；SageMaker AI 据此维护端点的托管缓存索引；端点用该索引为每个请求选择实例。索引只保存单向、截断的哈希指针，不存储提示、token ID、请求负载或 KV 张量。路由时端点对提示做分词并在索引中查找，按各候选实例的匹配长度与负载权衡选择；最长匹配实例过忙时跳过，无有效匹配或全部过忙则回退到负载感知路由，且无需像前缀感知路由那样配置并发阈值。索引随扩缩容更新：缩容时删除已移除实例的条目，扩容或替换实例时新实例从空缓存起步，短时间内延迟可能偏高。该策略仅在至少两个实例或至少两个推理组件副本时生效，单实例下无效果。

与前缀感知路由的对比：前缀感知从请求本身推断缓存位置，按 PrefixLength 字节（Invoke API）或字符（OpenAI 兼容 API）匹配，每请求额外延迟约 1.3–1.9 毫秒，需配置 PrefixLength 和 ConcurrencyThreshold，适用于任意支持前缀缓存的容器；KV 感知依据容器上报的缓存状态，按 token 匹配最长缓存，短提示额外延迟为几毫秒、长提示更多（主要为分词开销），无需额外参数，但要求受支持容器并开启前缀缓存与 KV 缓存事件，且请求负载须为 OpenAI 兼容的 Completions 或 Chat Completions 格式。

此次发布后，SageMaker AI 实时端点共提供四种路由策略，可在端点配置的 RoutingConfig 中按生产变体设置：RANDOM（默认，随机分配）、LEAST\_OUTSTANDING\_REQUESTS（发给在途请求最少的实例）、PREFIX\_AWARE（按固定前缀哈希路由，超过 ConcurrencyThreshold 时溢出到其他实例）、KV\_AWARE（新增，按容器上报的缓存状态匹配并权衡负载，回退到负载感知路由）。

**「背景」** LLM 应用如聊天助手、检索增强生成（RAG）和带长系统提示的智能体，会发送大量以相同文本开头的请求。模型会把对提示已完成的计算保存在 GPU 显存的 KV 缓存中，当相同开头再次到达同一实例时即可跳过这部分计算。此前该系列第一部分推出的前缀感知路由仅从请求推断缓存位置，无法感知实例已驱逐缓存，也存在多轮对话在请求长度超过 PrefixLength 之前可能落到不同实例的问题；KV 感知路由针对这两点做了改进。

**「产品变化」** 新能力由五个可独立使用或串联组合的构建模块组成：

\- 自动标注（Auto-labeling）：可从无标注数据集、小型已标注种子集或零标注起步，内置分类、命名实体识别、抽取式问答、序数评分和摘要等任务类型，也支持自定义任务。用户用简短的标注规范描述任务，规范会先在用户自己的示例上验证，再对完整数据集标注。对于答案集合固定的任务，由多个模型组成的评审团对每行标注，其一致程度作为该行的置信度分数。

\- 数据转换（Data transformation）：用自然语言描述变更由系统生成代码，或使用去重、合并、拆分、过滤等内置操作，也可大规模运行用户自己的 Python 代码。
